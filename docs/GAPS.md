# SIRO 未考量事項（Gaps）

> 本文件列出 SIRO v2.0 計畫書中**尚未被涵蓋的關鍵問題**。每一項都對實際使用有重大影響，技術實現之前需要先決策。
>
> 產出時間：2026-06-02
> 來源：計畫書審視 + 同類型專案（桌寵 / 對話裝置 / AI companion）常見失誤清單

## 1. 隱私與個資 🔴

**為什麼之前漏了：**
計畫書著重「AI 能不能跑」，沒處理「AI 聽到 / 看到 / 記得什麼」這類個資問題。

**現況缺口：**

- 桌寵裝置 24 小時開著，持續接收音訊 / 視訊
- 對話紀錄、情緒、記憶長期累積
- 可能涉及：行事曆、通訊錄、密碼、健康資料、家人對話
- 完全沒寫「資料歸誰」「誰能讀」

**解法選項：**

| 選項 | 優點 | 缺點 |
|------|------|------|
| **全本地、零上雲** | 個資零外洩 | 失去雲端 LLM 能力 |
| **本地為主、雲端可選** | 彈性高 | 需要清楚的開關與標示 |
| **端對端加密 + 使用者掌控金鑰** | 即使硬碟被拔也讀不到 | 復雜、易用性差 |

**建議：**
預設 **全本地**，雲端 LLM 為「明確 opt-in 開關」，每次使用要二次確認。

**行動項目：**
- [ ] SECURITY.md 新增「資料所有權」章節
- [ ] 定義「桌寳記憶」資料結構 + 加密方式
- [ ] UI 上要有一個「忘記我講過的話」按鈕
- [ ] v1 試用前要寫 Privacy Policy（一頁 A4）

## 2. 多模態輸入（語音 / 視訊 / 觸控） 🟠

**為什麼之前漏了：**
README 提了「文字 / 語音 / 眼神」三種輸入，但技術堆疊章節只講了 WebSocket 與 LLM 整合，**STT / TTS / 視覺輸入的具體技術選型、模型、效能預算、隱私處理都沒寫**。

**現況缺口：**

| 模態 | 缺什麼 |
|------|--------|
| 語音輸入 (STT) | 用 whisper.cpp / vosk / 雲端 STT？本地推論延遲？ |
| 語音輸出 (TTS) | 選 edge-tts / piper / 雲端 TTS？聲線怎麼定？ |
| 視訊輸入 | 攝影機怎麼驅動？臉部追蹤要哪個模型？OpenCV / MediaPipe？ |
| 視線偵測 | 真的要追眼珠子？模型大小？延遲？ |
| 觸控 | 桌寳視窗能否被拖動、點擊？要不要多點觸控手勢？ |
| 多模態融合 | 同時輸入時怎麼仲裁？語音 + 眼神的 priority？ |

**解法選項：**

- **STT**：whisper.cpp（品質好，CPU 慢）/ faster-whisper（快，CUDA 加速）/ vosk（輕量，品質普通）
- **TTS**：piper（本地）/ edge-tts（雲端但免費）/ 雲端商用（高品質）
- **視覺**：MediaPipe Face Mesh（輕量，Google 開源）
- **多模態**：簡單方案 = 輪詢；進階方案 = event-driven 仲裁器

**建議：**
- Phase 1 先做「純文字對話 + TTS 輸出」跑通
- Phase 2 加 STT（whisper.cpp small）
- Phase 5 再加視覺（硬體到位才做）

**行動項目：**
- [ ] 補 STT/TTS 選型 ADR
- [ ] 定義「音訊輸入緩衝區」規格
- [ ] 決定攝影機驅動框架（v4l2 / MediaFoundation）

## 3. 角色 Persona 設計 🟠

**為什麼之前漏了：**
計畫書有「SIRO 角色」這個詞，但**角色的 schema、聲線、性格檔、表情清單都沒定義**。沒這個，換角色要重寫 code。

**現況缺口：**

- 角色設定存在哪？YAML / TOML / JSON？
- 一個裝置能裝幾個角色？1 個？可切換？
- 角色的「人設 prompt」怎麼管理？
- 預設表情（happy / sad / surprised / thinking…）誰定義？模型自帶？
- 角色的 TTS 聲線、語速、語氣 → 在哪裡指定？
- **最重要的：角色資料與程式碼分離**（讓非工程師能改）

**建議的 Persona Schema（YAML 範例）：**

```yaml
id: siro-default
name: SIRO
personality: |
  溫柔、有點毒舌、會吐槽使用者熬夜、記得使用者說過的話
voice:
  provider: piper
  model: zh_TW-female-medium
  speed: 1.0
  pitch: 0
expressions:
  default: idle.motion3.json
  happy: exp_happy.motion3.json
  sad: exp_sad.motion3.json
  thinking: exp_thinking.motion3.json
  surprised: exp_surprised.motion3.json
idle_motions:
  - idle_breathing.motion3.json
  - idle_blink.motion3.json
  - idle_look_around.motion3.json
idle_interval_seconds: [10, 30]
language: zh-TW
llm:
  system_prompt_file: prompts/siro-system.md
  temperature: 0.7
```

**行動項目：**
- [ ] 寫 `docs/PERSONA.md` 規範 schema
- [ ] 提供一個範例角色（SIRO 本人）
- [ ] 設計「角色包」目錄結構（讓使用者能 drop-in 新角色）

## 4. 離線 / 網路失敗 🟠

**為什麼之前漏了：**
計畫書強調「本地 LLM」，但**沒處理網路失敗時的行為**。OS 必然會遇到沒網路的場景（外出、Wi-Fi 死、ISP 掛）。

**現況缺口：**

| 失敗情境 | 計畫書說了什麼 | 實際會怎樣 |
|----------|----------------|------------|
| 網際網路斷 | 沒寫 | 雲端 LLM 不可用 |
| 雲端 LLM 服務掛 | 沒寫 | 角色「當機」 |
| Wi-Fi 切換 (4G <-> 家裡) | 沒寫 | WebSocket 斷線 |
| 雲端 STT/TTS 掛 | 沒寫 | 變啞巴 |
| OTA 升級中斷 | 沒寫 | 系統半壞 |

**建議的離線優先策略：**

```
[網路正常]
  └─ 雲端 LLM + 雲端 STT/TTS (品質好)

[網路斷]
  └─ 本地 LLM + 本地 STT/TTS (品質普通但能講)

[本地 LLM 也掛]
  └─ 降級為預設回應池 ("嗯嗯"、"我在想"、"稍等一下")
  └─ 角色變「思考中」表情，避免使用者以為當機
```

**行動項目：**
- [ ] bridge 加 health check 與 fallback 邏輯
- [ ] 定義「網路狀態」enum（online / degraded / offline）
- [ ] 預設回應池設計（避免 AI 死掉時完全沒反應）
- [ ] 桌面 icon 顯示網路狀態

## 5. 災難恢復（使用者視角） 🟡

**為什麼之前漏了：**
Phase 6 有「備份還原」章節，但**備份的是「OS image」**，沒寫「**桌寳的記憶 / 角色設定 / 對話歷史**」怎麼備。一般使用者不懂 Packer image。

**現況缺口：**

- 桌寳記得你叫什麼、住哪、過敏什麼、昨天心情不好 → 這些資料要備份
- 備份要 **加密**（個資）
- 還原要 **簡單**（爸媽會按的）
- 轉移（買新機 → 倒資料 → 5 分鐘回到原狀）

**建議的災難等級：**

| 等級 | 場景 | 恢復目標 | 方法 |
|------|------|----------|------|
| L1 | 角色記憶損毀 | < 5 分鐘 | 自動備份還原 |
| L2 | 系統當機 | < 2 分鐘 | systemd 重啟 |
| L3 | SSD 壞 | < 1 小時 | image restore |
| L4 | 整台丟了 | < 1 天 | 雲端加密備份 |

**行動項目：**
- [ ] 設計「桌寳備份包」格式（角色 + 記憶 + 設定 + 對話歷史）
- [ ] 桌面加「備份 / 還原」按鈕（不要叫使用者進 terminal）
- [ ] 預設每日本地備份 + 每週加密上傳（選配）
- [ ] 寫「故障排除手冊」給非工程師

## 6. OTA 升級 UX 🟡

**為什麼之前漏了：**
Phase 6 寫了 Packer image 與 OTA，但**沒寫「使用者在跟 AI 對話中突然要重啟」怎麼辦**。這是 UX 災難。

**現況缺口：**

- 升級時角色在做什麼？（講到一半斷掉？）
- 升級失敗 → 系統半壞 → 使用者卡住
- 強制升級 vs 排程升級？
- **升級中斷時記憶怎麼辦？**

**建議的升級時機：**

| 時機 | 行為 |
|------|------|
| 使用者閒置 30 分鐘 | 自動提示「要更新嗎？」 |
| 強制更新（資安） | 角色先說「我需要重啟一下」再重啟 |
| 失敗回滾 | 自動回滾到上個版本，角色說「剛剛有點不適」 |
| 升級中斷 | 開機自動偵測並修復，否則回出廠 |

**行動項目：**
- [ ] 定義「升級狀態」state machine
- [ ] 角色在升級前要主動告知
- [ ] 升級失敗 → 自動回滾 + 角色解釋
- [ ] 升級時間避開使用者常用時段

## 7. 成功指標 KPI 🟡

**為什麼之前漏了：**
6 個 Phase 結束，**沒寫「怎樣算完成」**。沒有 KPI = 專案永遠「還沒做完」。

**建議 KPI：**

| 面向 | 指標 | 目標 |
|------|------|------|
| 啟動 | 開機到對話就緒 | < 30 秒 |
| 反應 | 使用者輸入到角色回應 | < 2 秒（本地）/ < 5 秒（雲端） |
| 穩定 | 24/7 連續運行 | 7 天無當機 |
| 記憶 | 角色記得 N 天前對話 | N ≥ 30 |
| 表情 | 表情切換延遲 | < 200ms |
| 語音 | TTS 開始播放 | < 1.5 秒 |
| 隱私 | 預設資料外洩風險 | 0 |
| 可用 | 5 歲到 80 歲會用 | v2 驗證 |

**行動項目：**
- [ ] 把 KPI 寫進 PLAN.md
- [ ] Phase 結束時驗收要量化
- [ ] 開一個 Grafana / 簡單 log 統計

## 8. 多人多裝置識別 🟡

**為什麼之前漏了：**
v1 試用期是 2-10 台給親友，**沒寫「A 家的桌寳記憶 vs B 家的桌寳」要不要隔離**。親友之間可能會互相看到對話。

**現況缺口：**

- 同一台被多人用（爸媽小孩）→ 怎麼辨識？
- 多台裝置之間要不要同步記憶？
- 「家人模式」 vs 「私人模式」

**建議方案：**

| 識別方式 | 優點 | 缺點 |
|----------|------|------|
| **聲紋辨識** | 自然、不用操作 | 多人用會累、誤判 |
| **人臉辨識**（攝影機） | 自然 | 隱私顧慮、化妝影響 |
| **手動切換帳號** | 簡單、隱私 | 不自然、易忘 |
| **裝置隔離**（一人一台） | 零設計 | 硬體成本 |

**建議：**
- 預設**裝置 = 帳號**（一人一台）
- 同台多人用 → 簡單人臉切換（v2 才做）
- 多台之間**不自動同步**（避免隱私問題），使用者可手動匯出匯入

**行動項目：**
- [ ] 定義「使用者 profile」schema
- [ ] 決定隱私預設值（裝置隔離）
- [ ] 文件寫清楚「誰會看到什麼」

## 9. 降級路徑（失敗展示） 🟡

**為什麼之前漏了：**
計畫書有「失敗處理」表格，但**沒寫「使用者會看到什麼」**。技術的「自動重啟」對使用者是「桌寳怎麼突然消失」。

**現況缺口：**

| 失敗 | 計畫書說 | 使用者視角 |
|------|----------|------------|
| LLM 死 | subprocess 錯誤回傳 | 角色當機？卡住？ |
| Live2D 當掉 | 重連機制 | 黑屏？藍屏？桌寳不見？ |
| 麥克風壞 | ? | 打字能用嗎？ |
| Rust 層崩潰 | watchdog 重啟 | 桌寳重啟會嚇到人 |
| 對話歷史損毀 | ? | 角色「失憶」？ |

**建議的降級行為：**

```
[任何子系統失敗]
  └─ 角色進入「思考中」表情 + 預設回應
  └─ 同時 log 詳細錯誤給維運
  └─ 不要直接重啟桌寳（嚇人）
  └─ 30 秒無法恢復才顯示「我需要重啟一下」+ 倒數 5 秒
```

**行動項目：**
- [ ] 為每個子系統定義「失敗 → 使用者會看到什麼」
- [ ] 設計「角色解釋失敗」的話術（不要冷冰冰的錯誤訊息）
- [ ] 桌面要有「強制恢復」按鈕（重新載入某個子系統）

## 10. i18n / 在地化 🟢

**為什麼之前漏了：**
你是繁中使用者，整份文件繁中、計畫書繁中。**但 code 內的 log、UI 字串、prompt 模板的語言沒規範**。早期不定，之後改會大爆炸。

**現況缺口：**

- LLM system prompt 用中文寫死？
- UI 字串放在哪？
- TTS 聲線要繁中？
- log 用中文還是英文？
- 之後想加日文 / 英文要怎麼設計？

**建議：**

| 項目 | 規範 |
|------|------|
| UI 字串 | 全部抽到 `i18n/zh-TW.json` 之類 |
| System prompt | 隨角色 Persona 走（不同角色可不同語） |
| TTS 預設 | 跟角色 Persona 走 |
| Log | 英文（給工程師看），UI 提示在地化 |
| 文件 | 主要繁中，可選英文版 |

**行動項目：**
- [ ] 抽 UI 字串到 i18n 檔
- [ ] 角色 Persona 加 `language` 欄位
- [ ] log 規範統一英文
